# 2027 工创赛智能搬运视觉方案总结

## 1. 比赛视觉需求与约束

依据《2027年第十届中国大学生工程实践与创新能力大赛智能+工程创新赛道竞赛命题与运行》，智能搬运机器人的视觉系统需要重点满足以下要求：

- 机器人必须完全自主运行，能够读取任务二维码，并识别物料的位置、颜色和形状。
- 场地内侧竖直安装一块 A4 横向二维码板，二维码位于中央，尺寸为 80 mm × 80 mm，位置在规定范围内随机摆放。
- 初赛任务码由四组三位数组成，例如 `156+123+516+231`，包含两批物料的颜色顺序及放置位置。
- 初赛物料为 ABS 或 PLA 3D 打印件，单件尺寸不超过 80 mm、重量不超过 100 g。
- 初赛可能出现红、黄、蓝、绿、黑、浅蓝六种颜色，实物存在一定色差。
- 初赛中三种待搬运物料形状相同；决赛可能出现圆柱体、方形体、三角形、球体、锥体和组合体等多种形状。
- 原料区为直径 300 mm 的旋转圆盘，转速约 6～10 秒/圈，并会按现场设定停顿。
- 传感器、电机和处理器的种类及数量不限，但机器人只能使用一个安装在车内的总电源。
- 不允许遮挡场地，只允许垂直向下补光，因此前向二维码识别不能依赖朝向二维码板的补光灯。
- 机器人上部必须安装醒目的任务码显示装置，字体高度不小于 12 mm，并显示任务码和任务完成统计信息。

## 2. 总体设计原则

二维码读取和物料识别的光学方向、工作距离、算法复杂度以及实时性要求完全不同。最可靠的设计不是让一个处理器和一台摄像头频繁切换任务，而是将两个功能拆分：

```text
前向二维码识别模块 ── UART ──┐
                              ├── STM32主控 ── 底盘、机械臂、显示屏
下视物料视觉模块 ─── UART ───┘
```

STM32负责比赛状态机、运动控制、机械臂和显示；视觉模块只输出经过校验的任务码、颜色、形状、中心坐标和置信度。正式比赛流程不依赖无线网络、图传或场外电脑。

## 3. 各种硬件方案比较

### 3.1 树莓派 5 双摄方案

组成：树莓派 5、前向二维码摄像头、下视物料摄像头、STM32。

优点：

- 两个板载 MIPI 接口可以同时连接两台摄像头。
- Python、OpenCV和Picamera2生态成熟，开发和现场修改方便。
- 适合保存大量原始图像，便于离线分析和重新标定。
- 对二维码、颜色分割、轮廓识别及轻量神经网络均有成熟实现。
- 决赛现场若增加新形状或新算法，软件调整速度较快。

缺点：

- 功耗、体积和散热需求高于智能相机。
- Linux启动时间较长，SD卡意外断电存在损坏风险。
- 双摄、串口、图传和视觉算法集中在同一系统中，软件故障影响范围较大。
- 本题初赛主要是二维码和颜色识别，树莓派大部分通用计算能力没有得到利用。

适用情况：团队熟悉Python/OpenCV，强调现场修改能力，且能够接受较高功耗和系统维护工作。

### 3.2 单块 K230 双摄方案

组成：CanMV-K230、两路摄像头、STM32。

优点：

- K230内置KPU，运行轻量目标检测模型效率高。
- 功耗、体积和成本通常低于树莓派或Jetson。
- 启动快，适合车载嵌入式应用。
- 芯片本身支持多路MIPI CSI和多传感器ISP处理。

缺点：

- 芯片支持多路摄像头不等于具体开发板已经方便、稳定地引出多路接口。
- 不同开发板版本的供电、传感器型号、固件和驱动配置可能不同。
- 双摄并发会增加驱动、内存、ISP和调试复杂度。
- nncase模型转换和K230部署流程不如普通Python/OpenCV灵活。
- 为读取一次性二维码而增加双摄集成风险，收益较低。

适用情况：团队已经有K230多摄经验，并且购买的开发板版本已经完成双摄实测。

### 3.3 二维码模组 + 树莓派/CM5物料视觉

组成：UART二维码扫码模组、树莓派5或CM5、下视摄像头、STM32。

优点：

- 二维码识别由专用硬件完成，树莓派只处理物料视觉。
- 保留OpenCV和Python的开发灵活性。
- CM5可选eMMC，体积和存储可靠性优于普通树莓派开发板。
- 模块分工清晰，二维码和物料识别互不干扰。

缺点：

- 总成本、功耗和散热仍高于K230方案。
- CM5需要载板，可能增加硬件设计工作。
- 对当前初赛任务而言算力仍有较大余量。

适用情况：决赛任务变化较大、团队主要掌握Python，或者需要快速开发复杂视觉功能。

### 3.4 二维码模组 + OpenMV N6物料视觉

组成：UART二维码扫码模组、OpenMV N6下视智能相机、STM32。

优点：

- OpenMV N6自带彩色全局快门相机，适合旋转物料和机械运动场景。
- 功耗低、启动快、体积小，不依赖Linux系统。
- 支持MicroPython、传统视觉和轻量YOLO目标检测。
- UART直接输出结果，系统隔离性和实时性好。
- M12镜头可更换，便于匹配转盘尺寸和安装高度。

缺点：

- 单价较高，不符合低预算优先目标。
- 国内供货和售后便利性可能不如常见K230开发板。
- 相比完整Linux平台，第三方Python软件包和桌面调试工具较少。

适用情况：预算充足，重视低功耗、快速启动和全局快门，希望获得较高的整机可靠性。

### 3.5 二维码模组 + K230物料视觉

组成：UART二维码扫码模组、单摄CanMV-K230、STM32。

优点：

- K230只处理一台下视摄像头，避开双摄驱动和资源分配风险。
- 颜色、轮廓、几何特征以及小型YOLO均可实现。
- 功耗、体积和采购成本较低。
- 启动快，可通过UART与STM32构建简单可靠的协议。
- 二维码和物料识别相互隔离，故障容易定位。
- 能够复用CanMV MicroPython及K230现有视觉示例。

缺点：

- 模型转换和部署不如树莓派上的Python流程直接。
- 不同开发板和固件版本之间可能存在API差异。
- 套装OV5647是滚动快门；若物料高速运动，需要等待转盘停稳或缩短曝光。
- 现场调试界面和数据记录能力不如完整Linux平台。

适用情况：预算有限，希望兼顾初赛稳定性和决赛AI扩展能力。本项目最终选择该方案。

### 3.6 Jetson Orin Nano方案

优点：

- CUDA、TensorRT和深度学习生态成熟。
- AI算力强，适合复杂目标检测、分割、三维视觉和多模型并行。
- 支持多路摄像头和大型神经网络。

缺点：

- 成本、功耗和散热需求明显偏高。
- 对六色物料和简单几何体属于严重算力过剩。
- 电源和启动维护会增加整车风险。

结论：除非决赛明确要求复杂三维视觉或大模型，否则不建议使用。

### 3.7 RK3588、香橙派等NPU开发板

优点：算力和接口丰富，价格通常低于Jetson，适合运行NPU模型。

缺点：摄像头驱动、系统镜像、NPU工具链和不同厂商板卡之间的一致性较差，可能花费大量时间解决平台问题。

结论：已有成熟经验可以采用，不适合作为首次参赛项目的低风险方案。

### 3.8 OpenMV H7 Plus方案

优点：低功耗、MicroPython易用，二维码、颜色、AprilTag和简单分类功能成熟；参考项目已有完整应用案例。

缺点：算力有限，复杂模型性能不足；该型号已停止常规生产，不适合新项目长期采购。

结论：已有硬件可继续使用，不建议新购作为主方案。

## 4. 最终选择

本项目采用以下低成本分布式方案：

```text
                 ┌─ 前向GM65/GM73类UART扫码模组
STM32主控制器 ───┤
                 └─ 下视CanMV-K230 + OV5647摄像头

STM32同时连接：任务码显示屏、底盘控制器、机械臂控制器和必要传感器。
```

选择理由：

1. 二维码是格式固定、只需读取一次的任务，专用扫码模组成本低、实现简单。
2. K230只连接一台下视摄像头，显著降低驱动和并发风险。
3. 初赛使用传统颜色和轮廓算法即可，K230算力充足。
4. 决赛若出现多形状物体，可在K230上追加轻量分类或目标检测模型。
5. 两个视觉模块分别通过UART输出结果，STM32保持唯一比赛状态机。
6. 无需无线网络、场外电脑或图传，符合自主运行要求并降低现场干扰风险。

## 6. 算法路线

### 6.1 二维码

- 车辆移动到二维码板前并停车，再触发扫码，不边走边识别。
- 扫描模块输出后由STM32校验任务码格式和数字范围。
- 推荐连续得到两到三次相同结果后才确认任务。
- 任务码确认后立即显示，并保存至STM32状态机。
- 扫码模块的白灯和红色瞄准灯必须关闭；若无法关闭，应更换模块或事先取得组委会书面确认。

### 6.2 初赛物料识别

初赛优先使用传统视觉，不应一开始就依赖YOLO：

1. 固定摄像头、补光亮度、曝光和白平衡。
2. 根据直径300mm转盘设置固定ROI。
3. 使用Lab颜色距离为主、HSV阈值为辅进行六色分割。
4. 对掩膜进行开闭运算和连通域过滤。
5. 通过轮廓面积、长宽、圆度等条件排除背景干扰。
6. 输出颜色、中心像素坐标、置信度和画面序号。
7. 使用平面单应性将像素坐标转换为机器人坐标。
8. 连续多帧位置变化小于阈值后才允许抓取。

### 6.3 决赛扩展

- 简单形状优先使用轮廓、凸包、圆度、Hu矩和多边形拟合。
- 传统方法无法稳定区分组合体时，再训练轻量分类或YOLO模型并部署到K230。
- 决赛模型不能替代颜色和几何规则，应保留传统视觉作为回退方案。

## 8. 后续实施顺序

1. 购买并单独点亮CanMV-K230及OV5647摄像头。
2. 使用严格80mm尺寸的二维码板测试扫码模组，并确认关闭补光后仍能稳定识别。
3. 建立K230到STM32的3.3V UART通信和心跳机制。
4. 制作六种颜色的真实ABS/PLA样品，搭建直径300mm转盘和垂直向下照明。
5. 完成颜色识别、稳定帧判断和像素到机械坐标标定。
6. 将任务码解析、识别结果和抓取流程接入STM32状态机。
7. 增加上电自启动、看门狗、通信超时和识别失败回退。
8. 在不同色温、阴影、距离、偏角、物料色差和电机干扰条件下进行整车压力测试。

## 9. 下单前仍需确认的信息

- STM32的具体型号及可用UART数量。
- 车辆主电池的串数、标称电压和满电电压。
- 摄像头预计距离原料转盘的高度。
- 机械臂抓取点是固定位置还是需要视觉输出二维偏差。
- 二维码板允许接近的最短距离。

确认以上信息后，再确定车载降压模块、UART引脚、摄像头焦距和最终通信协议。
