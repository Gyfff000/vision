# 第三步：自带摄像头识别颜色与中心

暂时没有独立USB摄像头，也没有比赛物块，本步骤先用K230自带摄像头验证静态颜色检测。程序会在K230屏幕和电脑预览中显示彩色画面，检测模式下画框和中心十字，并在终端输出颜色编号与中心像素坐标。暂不连接机械动作。

程序：[examples/k230_color_blocks.py](../examples/k230_color_blocks.py)。只需运行这一个文件，不依赖新增板端库。使用CanMV IDE，或VS Code的CanMV插件连接板子后执行 `CanMV: Run Active Python Script`；不要用电脑本地Python运行按钮。先停止之前的扫码程序，避免摄像头被占用。沿用扫码程序的ST7701、640×480屏幕配置，采集格式改为RGB565彩色。

## 没有实物时怎么试

打开[六色测试图SVG](../assets/color/six-color-test-card.svg)，或[PNG](../assets/color/six-color-test-card.png)，放大显示在电脑屏幕上，让自带摄像头看到其中一块纯色区域。彩色纸片、彩色积木也可以。使用屏幕时避免反光、条纹和过曝；调整距离至清晰，保持屏幕亮度不变。先只试红色，不需要一次完成六种颜色。

这只能验证采样、检测和坐标输出流程。屏幕自发光的颜色、纸片颜色与真实物块不同；以后用实际比赛物块重新采样，不能把测试图结果直接当作比赛参数。

## 1. 采样一块红色

六组采样候选已保存。用户随后反馈黑色效果稍好，其他颜色效果差，因此当前程序设为 `MODE = "TUNE"`、`TUNE_COLOR_ID = 1`，先只诊断红色；六组参数均保留，不自动修改阈值。`SAMPLE_COLOR_ID = 6` 只影响采样模式。

本地运行文件统一为 `D:\K230_pro\k230_color_blocks.py`。停止旧程序，关闭原先带星号的旧编辑页签，重新打开该文件。恢复六色检测时改为 `MODE = "DETECT"`，运行后确认 `enabled_ids= [1, 2, 3, 4, 5, 6]`。先逐色检查标签，再同时展示两到三种颜色，移动目标观察坐标跟随，全部移出后检查 `NO_TARGET`。尤其检查黑色是否把背景当成目标，蓝与浅蓝是否互相误判。

截图底部出现了不完整的Traceback，无法据此判断具体原因；若重跑后再次出现，保留从Traceback到最后一行的完整错误信息，不把它认定为正常停止或某种已知故障。

以下是首次采集红色的通用步骤；重新采样时先切到 `SAMPLE`，设置对应编号，用纯色内部填满中央小框，将输出赋值行替换到该颜色的位置。

如需重新采红色，将文件开头设为：

```python
MODE = "SAMPLE"
SAMPLE_COLOR_ID = 1
```

运行后，K230屏幕出现中央小白框。让**红色内部填满这个小框**，框里不要包含边缘、背景、文字或高光。摄像头预热后等几秒，观察终端每秒输出的采样结果。例如：

```text
[SAMPLE] known_color=1 name=RED
THRESHOLDS[1] = (六个实际数字)
```

这里的颜色名称由你设置的 `SAMPLE_COLOR_ID` 指定，采样模式不自动判断颜色。六个数字是从当前小框统计出的LAB阈值候选，可能需要调整。等多次输出接近，复制其中一整行带实际数字的 `THRESHOLDS[1] = (...)`。

## 2. 粘贴参数并开始检测

停止程序，将刚复制的那一行粘贴到文件开头 `# Paste sampled assignments HERE` 的下一行，即 `THRESHOLDS` 字典**后面、函数外面**。然后改：

```python
MODE = "DETECT"
```

重新运行。把红色目标放在屏幕大灰框内；画面会显示检测框、`RED` 标签和中心十字，终端最多每250毫秒打印一组当前目标，例如：

```text
[BLOCK] id=1 name=RED cx=320 cy=240 pixels=2500 valid=1
```

数字只是格式示例。坐标原点在图像左上角，x向右、y向下，单位像素。十字表示颜色区域的像素质心，不是已标定的夹爪抓取点。移开目标后应输出 `[NO_TARGET] count=0`；目标左右移动时 `cx` 应随之增减。

`valid=1` 只表示通过当前大小过滤且没有检测到跨颜色框重叠，不代表物体已静止、一定是真实物块或可立即抓取。不同颜色检测框明显重叠时输出 `[AMBIGUOUS] ... valid=0`，需要调整阈值或分开目标。

## 3. 再扩展其他颜色

每次回到 `MODE = "SAMPLE"`，修改编号，用对应颜色填满小框，再将输出赋值行粘贴到同一位置。保留已采样颜色的赋值行，每个编号只留一行；未配置颜色保持 `None`，检测不会替你猜测它。

| 编号 | 颜色 | 屏幕名称 |
|---|---|---|
| 1 | 红 | RED |
| 2 | 黄 | YELLOW |
| 3 | 蓝 | BLUE |
| 4 | 绿 | GREEN |
| 5 | 黑 | BLACK |
| 6 | 浅蓝 | LIGHT_BLUE |

先单色成功，再试两种或三种混放；蓝/浅蓝需特别检查混淆，黑色需排除暗背景、阴影。摄像头或照明变化后重新检查采样。程序未假定固件支持锁定自动曝光/白平衡。

## 排查与本阶段验收

### 颜色差时先运行TUNE诊断

当前默认 `MODE = "TUNE"`、`TUNE_COLOR_ID = 1`，保留红色候选，仅检测红色以减少干扰。让红色内部填满中央小白框，同时保持目标位于大灰框内，摄像头、画面构成、照明和屏幕亮度尽量固定。不要在采样时只拍满屏纯色，而在检测时突然换成包含大量背景的远景。程序预热3秒后，每秒输出一组诊断：

```text
[TUNE] id=1 lab_mid=(...) outside=L
[FILTER] raw=... small_pixels=... small_area=... large_area=... unknown_code=... kept=...
[CANDIDATE] THRESHOLDS[1] = (...)
```

- `lab_mid`：中央小框当前LAB各通道的中位数；只有框内完全是指定颜色时才有诊断意义。
- `outside=L/A/B`：当前中央中位数超出现有阈值的通道；`NONE`仅表示中位数在范围内，不保证整块目标都匹配。
- `raw`：按30像素/30面积搜索下限得到的候选数，不是未过滤的全部像素或所有细碎色块。
- `small_pixels` / `small_area`：通过搜索下限后，仍未达到正常检测大小要求的候选数量。
- `large_area`：候选面积超过检测区一半，被当作大面积背景排除。目标太近、占画面太大时也可能触发。
- `kept`：通过当前过滤的候选数，不代表确认是真实物块。
- `CANDIDATE`：当前小框的阈值建议，不会自动应用或保存，避免把背景误学成目标。

先把红色固定在框内，保留连续三组完整诊断；再移开红色，观察是否还有错误检测框。根据实际超界通道和过滤原因调整，不直接把六种颜色范围全部放宽。颜色参数原始采样较窄（例如黄色L为92–100、浅蓝89–100），拍摄条件变化可能造成漏检，但当前尚未确认具体原因。TUNE支持来自当前固件已运行过的直方图百分位接口；没有加入未经本机验证的自动曝光或白平衡锁定调用。

诊断完成后改回 `MODE = "DETECT"` 做六色联合验证；要排查下一颜色时保持 `TUNE`，修改 `TUNE_COLOR_ID`。TUNE的所有图像测量仍在绘制文字和框之前完成。

- 只有采样框、没有检测框：检查是否已改为 `DETECT` 并重新运行。
- 提示 `Sample one color first`：没有粘贴有效阈值赋值行，或赋值行还在注释中。
- 一直 `NO_TARGET`：确认目标在大灰框内，清晰且足够大；重新采样。`MIN_PIXELS=150`、`MIN_AREA=200` 是初始过滤设置，可以按目标大小调整。
- 目标占画面太多却没框：默认排除大灰框面积一半以上的区域，稍移远目标。该过滤是减少整片背景误检，不是比赛尺寸限制。
- 背景也被框住：缩小检测范围、调整背景或重新采样；不能通过增大所有阈值解决。
- 同一目标出现多个颜色或 `AMBIGUOUS`：阈值交叉，需要重新采样并收紧易混淆范围，尤其蓝/浅蓝。
- 字符、屏幕或接口报错：保留完整报错及固件版本；桌面检查不能证明板端API完全兼容。

当前目标是：看到彩色实时画面；一种颜色出现框和十字；移动目标时坐标变化；移开后没有旧坐标；加入另一种颜色时编号正确。记录样品来源（屏幕/纸片/实物）、距离、照明和终端结果。

真实物块到位后才验证六色区分和光照变化；接着做工作平面坐标标定与转盘稳定判断，再接机械抓取。USB相机到手后单独验证扫码链路。

## 实现依据与验证边界

- [亚博多颜色识别例程](https://www.yahboom.net/public/upload/upload-html/1747305082/3.%20Multi-color%20recognition.html)：核对本模块彩色采集、色块检测、屏幕绘制接口。

本项目先完成图像测量，再绘制标记，避免绘图影响检测。桌面测试验证阈值范围、编号映射、大小过滤、歧义处理、空帧结果以及TUNE诊断计数和通道比较。用户已反馈联合检测效果差；新版TUNE仅完成桌面检查，诊断输出和改善效果待板端验证。
