# 2027 智能搬运视觉需求与 K230 + USB 摄像头方案

更新日期：2026-10-09（北京时间）。状态：需求分析完成，硬件与算法待实测。

## 1. 依据与范围

比赛依据为用户提供的《2027年第十届中国大学生工程实践与创新能力大赛 智能+工程创新赛道竞赛命题与运行》（附件2-1，本地文件名为 `2027_smart_sorting_competition_brief.pdf`）。文件共20页，本文使用其中“智能搬运赛项”的第1-9页；不采用后续智能分拣、智能救援赛项的任务流程。

已提取相关正文，并核对第3-8页场地图、转盘图、圆环表、物料图及初赛流程。以下“规则”来自该版本文件，“建议”属于工程实现选择。未独立确认该文件是否为组委会最新发布版，后续补充通知需重新核对。

用户当前指定硬件是截图所示亚博 K230 视觉识别模块及一台独立 USB 摄像头。用户已明确：自带摄像头用于物块识别，USB摄像头用于扫码，两路图像都由K230处理。截图是产品介绍，不能确定手中实物的硬件版本、接口和固件。主控型号尚未提供，本文统一称为“主控”，不预设必须使用某款 STM32。

## 2. 先明确初赛完整流程

```text
一键启动
  -> 到二维码板前读取任务、校验并显示
  -> 原料区：按第一批颜色顺序逐个抓取，每个先放上车
  -> 粗加工区：按第一批位置逐个放置
  -> 粗加工区：按顺序重新抓回车上
  -> 暂存区：按第一批位置逐个放置
  -> 返回原料区：按第二批颜色顺序逐个抓取并放上车
  -> 粗加工区：按第二批位置放置，再按顺序抓回车上
  -> 暂存区：按同色关系叠放到第一批物料上
  -> 返回抽签确定的启停区，显示完成统计
```

规则第7-8页要求：每次抓一个，先放到车上才能抓下一个；跨区域运送不能一直用手爪夹着物料。视觉和主控之间需要有“已检测”“已执行”“已确认”的区分，不能把发出抓取指令当作抓取成功。

## 3. 视觉任务、输出及优先级

| 任务 | 规则或实际作用 | 视觉需要提供 | 实现阶段 |
|---|---|---|---|
| 任务二维码 | 初赛直接要求；第6-7页 | 原始任务字符串、有效性、确认状态 | 必做 |
| 六色物料识别 | 选对物料并遵守顺序；第5-6页 | 颜色编号、候选目标、置信度 | 必做 |
| 抓取位置与稳定判断 | 转盘会转动、停止点有偏差；第4页 | 目标中心、机械坐标偏差、稳定标志、帧时间 | 必做 |
| 圆环与工位定位 | 粗加工区和暂存区按编号准确放置；第4-5页 | 目标编号、圆环中心、放置偏差 | 必做 |
| 粗加工区二次抓取 | 第一、第二批均需放下再抓回；第7-8页 | 已放物料的颜色、位置和有效性 | 必做 |
| 暂存区同色码垛 | 第二批叠在正确的第一批同色物料上；第8页 | 已存物料颜色、上表面中心、遮挡/异常状态 | 必做 |
| 动作结果复核 | 支持正确抓取/放置统计；第2、8页 | 目标消失、到位、空位或倾倒等可观测证据 | 与机构联合实现 |
| 车道定位、避障、回库 | 机器人必须完成；第1、3、8页 | 如分配给视觉则输出车道/障碍/停靠偏差 | 按整车传感器分工 |
| 多形状、姿态和装配 | 决赛物料及任务现场公布；第1、3、6、9页 | 形状类别；必要时输出姿态和装配对准信息 | 预留扩展 |

规则列有二维码、条码、图形、数字、文字等读取能力，但明确的初赛入口是二维码。先实现二维码与工位数字1/2/3识别；通用条码和文字识别按具体任务扩展。规则没有要求初赛必须使用 YOLO、SLAM 或全视觉导航。

## 4. 任务码解析必须正确

格式为 `AAA+BBB+CCC+DDD`，颜色编号为：

| 编号 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| 颜色 | 红 | 黄 | 蓝 | 绿 | 黑 | 浅蓝 |

- AAA：第一批三个物料的颜色及搬运顺序。
- BBB：第一批在粗加工区及暂存区的位置，与 AAA 逐项对应。
- CCC：第二批三个物料的颜色及搬运顺序。
- DDD：第二批在粗加工区的位置，与 CCC 逐项对应。
- 第二批在暂存区的位置由“第一批同色物料在哪里”确定，不能直接使用 DDD。

规则示例 `156+123+516+231` 展开如下：

| 批次/顺序 | 颜色 | 粗加工区 | 暂存区 |
|---|---|---|---|
| 第一批1 | 红 | 1号位 | 1号位底层 |
| 第一批2 | 黑 | 2号位 | 2号位底层 |
| 第一批3 | 浅蓝 | 3号位 | 3号位底层 |
| 第二批1 | 黑 | 2号位 | 2号位黑色物料上方 |
| 第二批2 | 红 | 3号位 | 1号位红色物料上方 |
| 第二批3 | 浅蓝 | 1号位 | 3号位浅蓝物料上方 |

建议：校验四组三位数、分隔符、颜色范围1-6、工位范围1-3；按“三种不同颜色、每色两个”的初赛语义检查颜色集合和工位排列。连续多次一致后确认，保留原始字符串。异常任务上报主控，不自动猜测或纠正。

## 5. 对视觉设计有影响的尺寸和条件

| 项目 | 本版规则 | 设计影响 |
|---|---|---|
| 二维码板 | A4横放、竖直安装；二维码80×80 mm含边框；位置在规定范围随机，第6页 | 前向视角、允许距离、对焦和搜索范围需实测 |
| 场地 | 2400×2400 mm；中间十字灰色车道宽400 mm，第3页 | 不能依赖实验室固定停车误差 |
| 车道与障碍 | 完全离开启停区后仅可在灰色车道行驶；黑色障碍φ50×100 mm随机摆放，第3页 | 主控需有车道约束及可靠避障方案 |
| 原料转盘 | 直径300 mm、高80-100 mm；方向随机；6-10秒/圈；停顿次数/时间现场确定，第4页 | 需识别实际停稳状态，不能只用固定延时 |
| 粗加工/暂存区 | 580×150 mm；圆环带编号，第4-5页 | 识别编号或先建立工位映射，避免视角反转导致1/3颠倒 |
| 物料 | 尺寸不超过80 mm、重量不超过100 g；六色且存在色差，第5页 | 使用真实ABS/PLA样品调参，重点测试蓝/浅蓝和黑色/阴影 |
| 初赛图示物料 | 图5：高60 mm、底部φ50 mm、顶部φ30 mm，第6页 | 图像轮廓中心未必等于机械夹取点，须结合夹爪位置标定 |
| 放置评分 | 各级圆环外径依次为φ+3、φ+8、φ+15、φ+25、φ+35、φ+45 mm；对应15、10、7、5、3、1分；环外/倾倒0分，第5页 | 高分依赖视觉、停车与机构的共同精度 |
| 补光 | 不允许遮挡场地，仅允许垂直向下补光，第2页 | 下视照明按规则安装，前向扫码测试使用现场环境光 |
| 任务显示 | 车上部醒目、亮光、不遮挡；字体高至少12 mm，第2页 | K230自带屏能否达标需测实物，不能默认满足 |
| 电源/控制 | 车内一个电源且比赛含调试不能更换；完全自主，允许笔记本通信但运行时不能触碰或遥控，第1-2页 | 模块共用车内总电源；建议车上完成识别和控制 |

从φ50 mm物料与φ53 mm一环可估算，理想圆形投影的单侧余量仅1.5 mm。这是几何估算，不是新增官方容差，也不代表视觉单独必须达到或已达到1.5 mm；正式评分仍按第8页所述圆环可见性判断。应测试完整链路误差，而非只看检测框是否居中。

## 6. K230 与独立 USB 摄像头如何分工

按用户已确认的功能分工，建议安装布局：

```text
K230模块自带摄像头：朝向转盘和放置区域，负责物料、圆环、码垛定位
独立USB摄像头：前向采集二维码图像
                   |
       K230：物块视觉算法 + 二维码解码
                   |
           UART等有线结果通信
                   |
        主控：任务流程、底盘、机械臂、显示及统计
```

USB摄像头只负责提供图像，二维码检测、解码和任务校验在K230上完成，不依赖摄像头自身输出已解码的任务字符串。

该布局要求外接相机由 K230 作为 USB 主机采集，实物接口与固件尚未验证。若安装后下视相机无法同时看到转盘、圆环及码垛表面，需要调整停车位、安装位置或相机机构；两台相机的视场覆盖必须在整车结构确定前验证。

初赛先扫码、后搬运，建议先验证“USB相机扫码 -> 释放扫码相机资源 -> 自带相机识别物块”的分阶段切换，避免一开始依赖双摄同时工作。若整车需要一台相机导航、另一台持续抓放，则另行验证并发资源、帧率、内存和可靠性。

### USB兼容性的已知与未知

已知：嘉楠通用 CanMV 文档已有 `media.uvc`，提供检测、模式枚举、协商和取帧接口，默认单个 UVC 相机；main 文档注明可能包含未发布功能。[官方UVC文档](https://www.kendryte.com/k230_canmv/zh/main/api/mpp/media_uvc.html)

未知：亚博这款实物是否引出可用 Host/OTG、当前固件是否有对应模块、相机是否匹配。Type-C能连接电脑不证明能接USB相机。

验证顺序：

1. 记录准确板卡型号、硬件版本、固件版本，以及USB相机型号和输出模式。
2. 按该板资料核实主机接口、接线和供电，不盲刷其它开发板固件。
3. 按该固件自带例程检测并枚举相机，记录实际协商的分辨率、格式和帧率。
4. 检查图像色彩转换及算法输入是否匹配，实测连续取帧、掉帧和内存。
5. 最后再测自带相机与USB相机切换、需要时的并发，以及电机动作中的供电稳定性。

亚博官方资料提供其专用固件、相机和串口等教程，但目前没有取得本实物的 USB Host 接线及外接相机实测证据。[亚博K230资料](https://admin.yahboom.com/study/K230)

## 7. 算法路线与主控接口

### 二维码

由独立USB摄像头采集画面，在K230上完成二维码检测与解码。建议停车读取，校验内容后交给主控。识别超时则在允许区域内调整姿态/距离重试；不无限等待。任务显示和整车流程归主控管理。

### 颜色与抓取

使用K230自带摄像头，固定安装和照明后采样六色实物，使用Lab/HSV分割、连通域和轮廓过滤；多帧关联目标，估计位置变化。只有目标可见、稳定、在可抓取区域且结果新鲜时，才提供“可抓取”状态。优先利用转盘停顿，不在第一版实现追着运动物料抓取。

黑色要结合物料区域和形状排除阴影/圆环；蓝色与浅蓝不能只凭色相，需要结合亮度、饱和度及真实样本。初赛同形状，不必先训练六类检测网络。

### 放置与二次抓取

识别圆环/椭圆中心和数字编号，建立工位坐标；物料挡住编号时保留可信映射并用可见几何复核。放下后重新观测位置，粗加工区抓回时重新定位，不能完全依赖上一条放置指令。

### 标定与码垛

完成镜头畸变、相机与机器人坐标关系标定。转盘、加工台、暂存台和码垛上表面高度不同；不能无条件共用一个平面映射。固定相机可按工作平面分别标定，运动相机还需相机与机械臂关系。单目相机不能自动保证任意高度三维定位。

码垛优先寻找第一批同色物料的上表面中心，并结合已知层高和机构反馈；遇到遮挡、偏移或倾倒时停止盲放，交给主控重定位或退出当前动作。

### 通信与统计

视觉输出建议包含：请求/动作编号、模式、目标颜色或工位、坐标及坐标系、置信度、稳定标志、帧号/时间、有效期和错误状态。实际串口电平与引脚以板卡和主控资料为准。

主控负责命令、执行回执、超时、重试、载物位置、计数与显示。抓取/放置确认融合视觉和夹爪/载物传感器；单靠视觉看不到的过程应返回“未知”。动作编号用于防止重发造成重复计数。通信掉线或旧帧不能继续触发抓放。

## 8. 决赛扩展与待确认事项

决赛的场地区域、物料形状颜色、编码及获取方式现场公布，不能把初赛四组任务码和同形物料写死为唯一接口。保留任务解析、相机输入、颜色参数、形状识别及工位配置的替换能力。根据现场任务增加几何分类或轻量模型，必要时处理方向、姿态和装配对准。

下一步需要的实物信息：K230准确版本及固件、USB摄像头型号与输出格式、主控型号与通信接口、安装高度及朝向、夹爪方式、主电源规格、车道定位/避障由哪些传感器承担。
