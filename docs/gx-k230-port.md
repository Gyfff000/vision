# 银奖视觉算法的 K230 移植与验收记录

更新：2026-10-11。硬件：亚博 K230 1GB，CanMV v1.4.3-273db2e（2026-01-20）。IDE状态栏另显示0.4.0，以终端运行时版本为兼容性依据。

## 先运行哪个文件

| 文件 | 用途 |
|---|---|
| `k230_gx_self_test.py` | 检查板端 HSV、形态学、CRC 与任务码校验；不访问相机或外部串口 |
| `k230_silver_rgb.py` | 先测银奖方案：红、绿、蓝 HSV 阈值；也有 ARUCO、QR 模式和 V1 通信 |
| `k230_gx_vision.py` | 工创赛六色扩展、圆环、二维码、标定与同一通信接口 |
| `k230_red_check.py` | 小范围、单红色诊断，便于排除背景干扰 |
| `k230_install_autostart.py` | 保存银奖移植版和启动入口到 SD 卡，先备份旧文件 |

运行和转交同学的方法见压缩包根目录的《开始使用.md》。不用在 K230 上安装 PC 版 OpenCV。

## 原项目的实际内容

来源：[GX-Intelligent-Logistics-Silver](https://github.com/liaojingwu20041031/GX-Intelligent-Logistics-Silver)，核对的提交为 `c6359fbadc494e281ec3154aabb898b69419deeb`。主要读取 `raspberry_pi/color_detector.py`、`config.py`、`aruco_localizer.py`、`main.py`、`serial_comm.py`、`utils.py` 和 STM32 的 `Core/wc/smp.c`。

原项目使用树莓派和 cv2：RGB 三色 HSV 分割、5×5椭圆开闭运算、最大外轮廓及矩中心；ArUco采用 DICT_4X4_50 的0号标记。源码未做 README 所写的高斯预处理。原 UART 实现是9600波特率 ASCII E/F/G，协议说明中的另一套二进制格式与代码不一致。

压缩包 `reference/gx-silver-original/` 保存原项目完整 `raspberry_pi` 目录及原串口相关文件，仅用于对照；它们保留原作者代码，不能直接在 CanMV 运行。GitHub仓库以移植版及来源链接为主。

## 移植了什么，改了什么

K230实测没有 `cv2`，有 `image`、`ulab.numpy`、`cv_lite`。HSV转化由 ulab 完成，后接原生灰度掩膜、开闭运算、连通区域中心。银奖 RGB 入口保留原三色 HSV 参数；为了适配固件，开闭核改为3×3方形，处理图缩小一半，输出恢复640×480坐标。面积采用像素计数，和原轮廓面积不完全相同。

新增黄色、黑色、浅蓝、跨帧稳定、重叠歧义拒绝、边界过滤、区域限制、二维码任务校验、圆环中心和工作平面单应标定。六色参数是初始值，需要实物调参；不是银奖项目已经验证过的六色模型。

没有沿用原项目“没检测到仍回默认颜色/位置/零坐标”的行为。主控收到明确空结果或错误，CRC、序号和 DONE 用于完整性检查。UART格式与原STM32工程不兼容，使用本包配套 `stm32/vision_client.c`。

ArUco用相同字典做四旋转和一位纠错匹配，四边形透视采样；没有拿 AprilTag 代替。候选四边形检测和精度尚需板端实测。`assets/aruco/` 的标记仅供桌面验证，不表示允许在比赛场地额外贴标记。

## 已经验证

- 用户板端输出：`[GX_SELF_TEST] six HSV colors + morphology PASS`、`CRC + request + QR validation PASS`。
- 用户运行自带相机 COLOR 初版，约2.9～3.1帧/秒；输出检测坐标、歧义和空目标。日志也显示大面积黑色与零星红色干扰，且 stable 均为0，识别质量未通过验收。
- 随后加入 ROI、边缘过滤与最小面积调整，并提供单红诊断；最新过滤改动需要重新跑板端自检和相机测试，不能将旧自检当成新版实物准确率。
- 电脑端有算法检查及真正编译运行的 C99 跨语言报文测试，包括 CRC错误、丢包、分段、旧序号、超时、计时回绕、坐标未标定、任务码和自启动备份逻辑。
- 自启动安装器只经过电脑模拟 SD 卡文件测试；用户尚未提供真实板端 `INSTALL_OK` 或断电启动结果。

## 尚未验收的边界

USB摄像头未到位，UVC适配和阶段切换未测；串口型号/引脚未定，UART默认关闭，没有实际STM32收发记录；机械坐标没有实测标定。蓝/浅蓝、黑/阴影仍需实物区分。

同色物块当前只返回最大一个。圆环使用圆检测并合并同心环，编号由已确认朝向下的 `RING_SLOT_ROIS` 配置映射，未实现自主数字OCR；未配置时编号0且stable=0。斜视造成的椭圆、遮挡和码垛上表面需进一步验证。尚未实现倾倒识别、抓放成功复核、导航和决赛未知形状。此包是可继续联调的视觉工程首版，不能等同于完整比赛验收通过。

`valid=1`表示通过图像过滤，`stable=1`只表示最近4帧中心变化小于阈值，均不代表主控可以无条件抓取。像素轴向右/向下；毫米坐标只有本工作高度的标定和 ROI 生效才返回。

## 配置与标定

默认640×480画面；`REFERENCE_PIXEL`应改为夹爪轴对应像素。`DETECT_ROI`限制搜索区域，框边缘被截断的目标会被过滤。HSV使用 H=0～179、S/V=0～255，格式 `(H下,H上,S下,S上,V下,V上)`，不是旧LAB参数。红色有两个跨零区间。

可用 `MODE="HSV_SAMPLE"`、`SAMPLE_COLOR_ID`观察中央40×40色块中位数，再调 `HSV_RANGES`；红色中位数已处理色相跨零。调参时固定灯光、曝光条件、距离和背景，再逐色加入；主控通信可以先用PING和空目标测试，不必等颜色调完。

`tools/calibrate_plane.py`读取像素/毫米对应点 JSON，至少4个非共线点，建议8个以上覆盖工作区，打印9个单应矩阵数。把矩阵和有效区域填入 `PLANE_H/PLANE_ROI`，或分别填 `CALIBRATIONS` 的GRASP/PLACE/STACK。请求可带对应标定配置名。拟合误差只是训练点误差，还要用独立点验证；物块顶面、地面和堆叠高度不能共用未经验证的标定。

USB到位后才将 `QR_CAMERA="USB"`：适配器探测 `media.uvc`，协商640×480 MJPEG，采用软件转RGB565并按阶段切换相机。缺失模块、相机或格式会报错，不会悄悄换源。参考[官方UVC API](https://www.kendryte.com/k230_canmv/en/main/api/mpp/media_uvc.html)，实际固件支持仍以板端为准。
