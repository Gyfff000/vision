# STM32接入与动作接口

本包的两个C模块均为C99，不依赖某款STM32 HAL。实际UART型号、引脚、DMA/中断和机构由你们主控工程确定。通信与任务状态机已经实现；底盘、机械臂驱动不能在未知硬件下代写成可直接烧录的HAL工程。

## 串口底层

将vision_client.c/.h与competition_controller.c/.h加入工程，启用stdio/strtof/math对应标准库。K230外部UART为115200/8N1。ISR或DMA回调仅把字节放入环形缓冲；在主循环/任务内取出并调用competition_feed，随后周期调用competition_tick，传入STM32毫秒计时。缓冲溢出应停机报错，不能静默继续使用旧数据。建议接收缓冲至少1024字节，所有feed/tick和发送在同一主循环或同一线程串行执行。

```c
#include "competition_controller.h"
static CompetitionController controller;
// 以下函数使用你们现有驱动实现；名称不固定。
static const CompetitionIO robot_io = {
    Port_SendBytes,
    Robot_GotoCameraPose, Robot_GotoPoseFeedback,
    Robot_StartGrabOrPlace, Robot_ActionFeedback,
    Robot_StartReturnHome, Robot_ReturnHomeFeedback,
    Robot_StopAll
};
// 初始化后：competition_init(&controller, &robot_io);
// 标有“一键启动”的按键触发一次：competition_start(&controller, HAL_GetTick());
// 主循环：competition_feed(&controller, bytes, count);
//         competition_tick(&controller, HAL_GetTick());
```

Port_SendBytes的签名为void(const uint8_t*, size_t)，返回前必须保证已复制或发送完输入字节；输入指针指向临时发送缓冲，不能直接交给异步DMA后立即返回。可使用短报文阻塞发送，或先复制到自己的DMA发送队列。不要从中断里调用协议解析或机构动作。

初始化处于CC_WAIT_START，即使提前收到二维码也不自动移动。按键调用competition_start后先RESET清除调试阶段的旧任务，再等待本轮重新扫码和确认。不要在循环中反复调用start；错误后示例保持停机，重新参赛需按你们的操作流程重新初始化。

## CompetitionIO每个函数必须完成什么

- prepare_start(step)：导航到本步所在区域并调整相机/机械臂观察姿态。只有prepare_poll确认停车、姿态及区域正确，控制器才请求定位。区域切换前必须确认物料已经装车；同区下一物料可复用停靠，但不能忽略姿态要求。
- prepare_poll：-1失败，0处理中，1实际就绪。
- action_start(step, record)：依据step.pick/stack/color/slot/profile选择抓取、装车、放置或码垛；record仅在调用期间有效，要保存需复制结构体。抓取步骤必须包括放回车上。
- action_poll：-1失败，0处理中，1实际执行且复核成功。不能在刚发完舵机命令后就返回1。放置计数代表主控确认到位，不意味着裁判自动给满分。
- home_start/home_poll：返回抽签启停区，并确认实际到位。成功后控制器才向K230发送HOME_DONE。
- stop：立即停止底盘与机构，通信错误、定位超时、动作失败时调用。不是发送一个成功确认。

默认require_mm=1：只有新鲜、有效、稳定且已配置毫米标定的当前目标，才调用action_start。初始未标定时只显示/通信，不盲抓。若你们采用经过验证的像素闭环控制，可明确改require_mm=0，并由自己的动作函数解释像素误差；不可把它当作绕过标定的固定比例尺。

默认每请求1500ms超时，最多3次重试；定位等待30s、导航/动作/回库各30s（根据真实机构耗时调整），允许定位往返最多600ms。sequence用于拒绝旧响应，STEP确认使用token+步骤去重。若STEP应答丢失，只重发确认，不重新执行机构动作。

controller.grabs/places只在实际动作完成且确认收到ACK_STEP后累计，正常24步结束各12次。controller.state为CC_FINISHED且step=24时才表示回库和最后通信确认均完成；CC_FAULT时看error，并由用户停止后决定复位或人工调试，示例不自动跳过失败物料。

单独使用底层VisionClient也可以，分别调用vision_ack_task、vision_request_profile、vision_confirm_step、vision_home_done，遵守同样的状态和动作反馈规则。两种方式不要同时争用同一个串口/解析器。
