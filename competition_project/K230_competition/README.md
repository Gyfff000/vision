# K230 智能搬运比赛视觉工程

版本：FLOW_20261012_V1。基于你提供的 K230_vision_20261011(1).zip 整理，面向2027初赛完整流程；不再需要手动修改MODE从扫码切到颜色。

## 先安装，再测试

1. 将新包完整解压到电脑本地，例如 `D:\K230_pro\K230_competition_20261012`。不要在Windows左侧的CanMV便携设备目录中编辑代码。
2. 在CanMV IDE打开**本地的 `install.py`**，连接K230，停止旧程序，运行一次。
3. 应看到 `[INSTALL_OK] /sdcard/vision_releases/flow_001`（编号可能更大）和 `[INSTALL_OK] /sdcard/main.py`。它们都出现才算安装完成。
4. 断开IDE，断电重新供电。约3秒启动延时后，LCD先显示SCAN和实时扫码画面。启动输出必须有 `[FLOW_BUILD] FLOW_20261012_V1`，以及 `[FLOW_SOURCE]` 指出的实际目录。
5. 首次测试可在IDE运行 `self_test.py`，应打印一行 `[FLOW_SELF_TEST] ... PASS`。该自检使用合成图像，不证明真实物料准确率。

如果出厂GUI仍在运行，可依亚博官方说明按住KEY再上电，保持到IDE连接后松开，以临时跳过GUI后安装；正常自启动时不要一直按KEY。不刷固件、不删除boot.py或ybUtils。

## 当前一台摄像头怎样跑

```text
上电SCAN → 自带摄像头扫码 → 三次有效解码一致
→ WAIT_ACK：保存任务、显示任务并定时向STM32重发
→ STM32校验并TASK_ACK → 自动进入第一批原料COLOR
→ 主控依次完成24个抓放步骤并逐步确认
→ RETURN_HOME → 主控确认回到启停区 → COMPLETE
```

用 `assets/task-156-123-516-231.png` 测试。`Good`只是旧版扫码调试内容，不是有效比赛任务，本版本不会凭它启动搬运。物料还没准备好时可以先验证扫码、任务通信和空目标返回。

**没有STM32确认时停在WAIT_ACK是正常行为。** 不会靠延时假定任务已经送达。可用3.3V USB-TTL适配器和 `tools/serial_test.py COM号 --demo` 模拟确认；此工具只确认任务并读取第一步位置，不确认任何抓放动作。它使用外部UART，不能用IDE的USB COM代替。

同一台摄像头只能看到它实际朝向的区域。扫码时需要看到二维码板；后续需由停车/相机机构使其看到转盘和工位。软件模式切换不能改变镜头朝向。

## STM32接线与代码

K230默认UART3，115200、8N1、3.3V TTL。亚博12针排针：物理第5脚=GPIO32/TX，接STM32 RX；物理第3脚=GPIO33/RX，接STM32 TX；两板共地。

`stm32/vision_client.c/.h` 实现任务接收、CRC、序号、超时和结果解析。`stm32/competition_controller.c/.h` 实现两批24步骤、动作确认、重复确认保护、回库与统计。把四个文件加入主控工程，按 [主控接入](docs/主控接入.md) 绑定你们自己的串口、导航和机构函数。型号未确定，所以没有虚构某一款STM32的引脚或HAL工程。

完整通信格式见 [通信协议](docs/通信协议.md)。不要继续使用银奖原树莓派的E/F/G协议，也不要混用旧包中的STM32解析器。

## 后续接USB扫码摄像头

在**本地 `install.py` 顶部**只改这一行，然后重新运行安装器：

```python
QR_CAMERA = "USB"
```

颜色识别仍使用自带摄像头。现在保持 `"ONBOARD"`。接口按CanMV UVC预留；是否支持取决于本板Host接口、固件和相机格式，尚未用你们的USB相机实测。连接失败会报错，不会静默换成另一台相机。

## 修改怎样生效、为什么不再产生随机副本

常用配置可直接改本地 `install.py` 顶部，包括扫码相机、UART、处理缩放和IDE预览。保存、重新运行安装器、断电重启即可。

高级参数（颜色阈值、平面标定、工位映射）修改本地 `config.py` 后，在电脑运行：

```text
python tools/build_install.py
```

它会把最新配置和程序重新嵌入 `install.py`，然后仍按上述方式安装。不要修改config后运行未重建的旧安装器。

安装器在K230内部直接写文件、读回逐文件校验，全部成功后才更新固定的 `/sdcard/main.py`；上一个main.py保存在 `vision_backup`。`vision_releases/flow_001`、`flow_002` 是有意保留的完整版本目录，根目录main.py明确指定其中一个，和以前那些随机后缀副本不同。旧版根目录的k230_silver_rgb.py不再是新启动入口。不要把本地模板main.py单独覆盖到板上；请运行install.py。

这是运行程序安装，不是烧录固件。若断电恰好发生在根目录main.py替换的极短间隙，可能需要重新运行安装器恢复；先校验新版本再切入口能减少风险，不能保证任意断电条件下存储操作绝对原子。

## 帧率与显示

- LCD始终显示；默认关闭IDE图传，所以IDE帧缓冲没有新画面并不表示LCD没运行。需要IDE预览时改安装器顶部 `IDE_PREVIEW=True`。
- 颜色分割默认缩小到0.25倍；RAW区域实际处理120×90像素，坐标仍换算到640×480。扫码保留原分辨率，圆环独立使用0.5倍。
- 扫码后只计算任务涉及的三种颜色，返回当前步骤指定目标；不会每帧做六色分割。
- 显示每次取到画面就更新，颜色检测默认间隔100ms，扫码150ms；定位请求强制处理新图像。缓存框只用于显示，不通过串口当作新坐标发送。
- 降低终端打印频率，GC由每帧改为定时。打印 `[FLOW_PERF]` 分别报告显示FPS、检测FPS和各环节耗时。
- 真实帧率尚未在你板上测量，不承诺30FPS。缩小图像会损失小目标细节；需要精细对准可调回 `PROCESS_SCALE=0.5` 并重新验证MIN_PIXELS。

WAIT_ACK、PAUSED、RETURN_HOME、COMPLETE显示静态任务状态，不持续占用摄像头；此时FPS为0不是识别性能故障。

## 当前必须完成的现场配置

1. 实际物料的六色HSV阈值与误检测试。
2. PROCESS/STORE两组工位数字1/2/3与图像ROI的对应；未配置会报NO_SLOT_MAP，程序不猜工位。当前采用现场建立的工位映射，不包含数字OCR。
3. RAW/PROCESS/STORE/STACK不同工作高度的像素到机械坐标标定及独立验证；默认未标定时输出NA，主控示例不触发抓放。`tools/calibrate_plane.py`可从实测像素/毫米对拟合平面。
4. 机构动作反馈、装车检测、停车和回库确认。轮廓中心不自动等于夹爪抓取点，倾倒/遮挡时需要机构与视觉共同复核。

软件已连接完整初赛流程接口，但没有据此宣称整车通过比赛。决赛现场未知形状、装配和任务格式需按新规则扩展；车道导航、避障及电机/机械臂驱动属于主控工程。
